# ConstructClaim — static demo

This repository now contains an **early, local-only demonstration slice** of ConstructClaim. It is not the production financial evidence system described in [GOAL.md](GOAL.md), [SPEC.md](SPEC.md), and [TASK.md](TASK.md). The 24 images in `ui/` are layout references, not application data or evidence of functionality.

## Run locally

From the repository root, run `python -m http.server 8765` and open `http://localhost:8765/`. No npm install, account, API, database, or external service is used. The committed icons are generated by `tools/generate_icons.py` (Pillow is needed only to regenerate them). Use a local HTTP server or HTTPS: Service Workers and IndexedDB are not a supported workflow when opening `index.html` as a file.

The root `index.html` and all asset URLs use relative paths, so a GitHub Pages project site served from a repository subdirectory is possible. If publishing the demo is separately authorized, configure GitHub Pages to serve the **repository root** from the selected branch; no deployment workflow is included. Do not publish confidential information or enable production workflows on this static host.

## What works in this slice

- Responsive desktop rail / mobile bottom navigation for dashboard, projects, claims, inbox, evidence, device drafts, and settings, inspired by `DESIGN.md`.
- Synthetic project and claim records, search and receivable/payable filter. Values and document IDs are **illustrative**, not from the reference screenshots or any live tenant.
- New fictional claim draft: validate a month and illustrative positive amount, then save locally to IndexedDB. The saved state is shown only after the local transaction completes. Refresh to read it back; inspect or delete it under Device drafts/Settings. If storage fails, the form preserves input and reports failure.
- Static shell Service Worker, install manifest/icons, best-effort offline shell cache and visible user-controlled update prompt. `sw.js` cache version must be changed for each release that changes shell assets. Offline full-page reload failed under DevTools network emulation in the current checks; offline launch is **not verified** and requires a separate network-loss/device test.

## Deliberately not implemented

There is **no authentication, authorization, tenant isolation, server, database, real evidence upload, financial calculation, certificate issue, invoice/payment posting, audit ledger, AI, multi-user synchronization, or conflict resolution**. Device drafts are not queued server commands. Browser storage can be evicted or manually cleared; it is neither secure storage nor a backup. Do not enter real customer, contract, site, or financial data. The demo cannot claim that any submission, approval, sync or financial event occurred.

The production decision gates T-001–T-003 and E2E-01–E2E-18 in [TASK.md](TASK.md) remain open. After the demo is reviewed, resolve those decisions and build/test a separate authoritative system; do not promote device-local demo records into production data without an approved migration and security review.

## Checks

Run `node --check app.js && node --check storage.js && node --check sw.js` and `python -m json.tool manifest.webmanifest` for syntax. Browser-check at desktop and 390×844: navigation, validation, successful local write and reload, search/no-results, delete, storage error, mobile overflow, and offline/update behavior. These checks are not the production acceptance suite.
